# depgraph — визуализатор графа зависимостей пакетов NuGet

CLI-инструмент на Python, который строит граф зависимостей пакета формата .NET (NuGet),
печатает его в виде списка, ASCII-дерева и порядка загрузки, а также рисует диаграмму PlantUML
и сохраняет её в PNG.

Зависимости получаются напрямую из репозитория по HTTP (`.nuspec`), **без** менеджеров пакетов
(`dotnet`, `nuget`) и сторонних библиотек. Используется только стандартная библиотека Python.

## Требования

- Python 3.8 или новее.
- Для PNG — одно из двух:
  - **`plantuml.jar`** + Java + Graphviz (`dot`): `--plantuml-jar путь/plantuml.jar`
    (работает офлайн; именно этим способом получены картинки в `demo/`);
  - либо доступ в интернет: без `--plantuml-jar` изображение запрашивается у сервера PlantUML
    (`https://www.plantuml.com/plantuml`).
- Для реального режима — доступ к `https://api.nuget.org/v3/index.json`.
  Тестовый режим работает без сети.

## Структура репозитория

```
depgraph.py                     итоговая версия (совпадает со stage5)
stages/
  stage1_cli.py                 этап 1: CLI и конфигурация
  stage2_nuget.py               этап 2: прямые зависимости из NuGet
  stage3_graph.py               этап 3: граф, DFS, циклы, фильтр, тестовый режим
  stage4_load_order.py          этап 4: порядок загрузки
  stage5_visualization.py       этап 5: PlantUML, PNG, ASCII-дерево
test_repos/                     тестовые репозитории (формат — ниже)
demo/                           примеры результата: .puml и .png
```

Каждый файл в `stages/` — самостоятельный скрипт: состояние программы на конец соответствующего этапа.

## Параметры командной строки

| Опция | Описание |
|---|---|
| `-p, --package` | имя анализируемого пакета (обязательно) |
| `-r, --repo` | URL репозитория (service index NuGet v3) или путь к файлу тестового репозитория (обязательно) |
| `-t, --test-mode` | тестовый режим: `--repo` — путь к файлу описания графа |
| `-v, --version` | версия пакета, например `13.0.3` (вне тестового режима обязательна) |
| `-o, --output` | имя PNG-файла с графом, по умолчанию `graph.png` |
| `-a, --ascii-tree` | вывести зависимости в виде ASCII-дерева |
| `-f, --filter` | подстрока: пакеты, в имени которых она есть (без учёта регистра), не анализируются |
| `-l, --load-order` | вывести порядок загрузки зависимостей (вместо графа и изображения) |
| `--plantuml-jar` | путь к `plantuml.jar`; без него PNG строится через сервер PlantUML |

Все параметры проверяются при запуске; найденные ошибки выводятся списком.

## Примеры

Реальный репозиторий:

```
python depgraph.py -p Newtonsoft.Json -r https://api.nuget.org/v3/index.json -v 13.0.3 -a -o json.png --plantuml-jar plantuml.jar
python depgraph.py -p Microsoft.Extensions.Logging -r https://api.nuget.org/v3/index.json -v 8.0.0 -f Abstractions
python depgraph.py -p Serilog.Extensions.Logging -r https://api.nuget.org/v3/index.json -v 8.0.0 -l
```

Тестовый репозиторий:

```
python depgraph.py -p A -t -r test_repos/diamond.txt -a -o demo/diamond.png --plantuml-jar plantuml.jar
python depgraph.py -p A -t -r test_repos/cycle.txt
python depgraph.py -p A -t -r test_repos/complex.txt -f B
python depgraph.py -p A -t -r test_repos/complex.txt -l
```

Пример вывода (`test_repos/complex.txt`, `-a`):

```
Граф зависимостей пакета A: пакетов 5, рёбер 6
  A -> B, C
  B -> C
  C -> B, D
  D -> E
  E -> (нет зависимостей)
Циклические зависимости (1):
  B -> C -> B

ASCII-дерево зависимостей:
A
├── B
│   └── C
│       ├── B (цикл)
│       └── D
│           └── E
└── C (*)
(*) — поддерево показано выше; (цикл) — возврат к пакету-предку
```

## Формат тестового репозитория

Текстовый файл, по одной строке на пакет: `ИМЯ: зависимости через пробел`.
Имена — заглавные латинские буквы. Пустые строки и `# комментарии` игнорируются.

```
# ромб
A: B C
B: D
C: D
D:
```

Пакет, упомянутый только как зависимость, считается пакетом без зависимостей.
Ошибки файла (неверный формат, строчные буквы, повторное описание, пустой файл) сообщаются
с номером строки. В `test_repos/` лежат случаи: `chain`, `diamond`, `cycle`, `self_loop`,
`complex`, `unreachable` и четыре файла с ошибками (`bad_name`, `bad_format`, `duplicate`, `empty`).

## Как это работает

1. **Получение данных.** Из service index NuGet v3 берётся ресурс `PackageBaseAddress`, затем
   скачивается `{base}/{id}/{version}/{id}.nuspec` и разбирается через `xml.etree`.
   Учитываются разные пространства имён `.nuspec`, группы по target framework и зависимости без групп.
2. **Версии.** Диапазон версии (`[1.0, )`, `(, 2.0]`) заменяется нижней границей.
3. **Граф.** Рекурсивный DFS. Пакеты с подстрокой фильтра пропускаются вместе с их поддеревьями.
   Ребро в пакет, который сейчас в стеке рекурсии, сохраняется и фиксируется как цикл, но рекурсия в него
   не идёт; уже обработанный пакет не раскрывается повторно.
4. **Порядок загрузки.** Пост-порядок DFS: пакет идёт после всех своих зависимостей, корень последний.
   Циклы разрываются по обратному ребру, и программа сообщает, по каким.
5. **Визуализация.** Текст PlantUML (`.puml` сохраняется рядом с PNG; рёбра цикла — красный пунктир),
   затем PNG через `plantuml.jar` или сервер PlantUML. ASCII-дерево строится рекурсивным обходом.

## Коды возврата

| Код | Значение |
|---|---|
| 0 | успех |
| 2 | ошибка параметров командной строки |
| 3 | ошибка репозитория (сеть, 404, некорректные данные, ошибка файла тестового репозитория) |
| 4 | ошибка построения PNG (`.puml` при этом сохраняется) |

## Упрощения и ограничения

Эти пункты определяют, чем результат отличается от реального менеджера пакетов:

- **Версии.** Узел графа определяется именем пакета; при нескольких версиях одного пакета берётся
  первая встреченная. NuGet выбирает версию иначе (nearest wins, при конфликтах — наибольшая из нижних границ).
- **Target framework.** Зависимости объединяются по всем группам `.nuspec`, а `dotnet` берёт только группу,
  подходящую целевому фреймворку проекта. Поэтому в нашем графе может быть больше пакетов.
- **Диапазоны.** Исключающие границы трактуются как включающие.
- **Зависимости SDK** (метапакеты, подразумеваемые платформой), не описанные в `.nuspec`, не учитываются.
- **Циклы.** NuGet циклы не допускает; здесь они разрываются и показываются.
- **Глубина рекурсии.** Лимит рекурсии поднят до 5000; при его превышении выводится сообщение об ошибке.
- **Сервер PlantUML.** Для очень больших графов запрос не помещается в URL; используйте `--plantuml-jar`.

## Сравнение с штатными инструментами

Для сравнения с реальным менеджером создайте проект и добавьте пакет:

```
dotnet new console -n cmp && cd cmp
dotnet add package Newtonsoft.Json --version 13.0.3
dotnet list package --include-transitive
dotnet nuget why cmp.csproj <пакет>      # в новых версиях SDK: цепочки зависимостей
```

Подробные данные — в `obj/project.assets.json`. Сравнивайте состав пакетов, версии и пути зависимостей;
расхождения объясняются пунктами из раздела «Упрощения и ограничения». У `dotnet` нет понятия
«порядок загрузки»: пакеты скачиваются параллельно, а выводятся по алфавиту, поэтому сравнима только
корректность топологического порядка.

## Этапы и сообщения коммитов

| Этап | Файл | Сообщение коммита |
|---|---|---|
| 1 | `stages/stage1_cli.py` | `feat(cli): add minimal CLI prototype with config validation (stage 1)` |
| 2 | `stages/stage2_nuget.py` | `feat(nuget): fetch direct dependencies from NuGet v3 repository (stage 2)` |
| 3 | `stages/stage3_graph.py` | `feat(graph): build transitive dependency graph with recursive DFS, cycles and test mode (stage 3)` |
| 4 | `stages/stage4_load_order.py` | `feat(order): add dependency load order mode (stage 4)` |
| 5 | `stages/stage5_visualization.py` | `feat(visualization): PlantUML text, PNG rendering and ASCII tree (stage 5)` |

## Что проверено

- Проверка параметров: успешные запуски и ошибочные случаи для каждой опции.
- Тестовый репозиторий: цепочка, ромб, цикл, самоссылка, два цикла с общим хвостом, недостижимые пакеты,
  фильтр, ошибки формата файла.
- Порядок загрузки: автоматическая проверка на всех тестовых репозиториях, что зависимость стоит раньше
  зависимого (кроме разорванных рёбер цикла).
- Реальный режим: на локальном mock-сервере с форматами `index.json` и `.nuspec`
  (группы фреймворков, старый namespace, пакет без зависимостей, цикл, 404, битый XML, некорректный JSON,
  недоступный сервер).
- PNG: через `plantuml.jar` (Java 21, Graphviz 2.43); кодировщик для сервера PlantUML совпал с примером
  из документации, сетевой путь проверен на локальной заглушке.

Запуск на настоящем `api.nuget.org` и сравнение с `dotnet` нужно выполнить отдельно на машине с доступом в интернет.
